# Akun siswa langsung aktif: kebijakan provisioning

Saat Admin menambah siswa melalui **Pengguna**, Admin wajib mengisi password atau menggunakan tombol **Generate password**. Siswa dibuat menggunakan Supabase Auth Admin `createUser`, dengan password dan `email_confirm: true`; profil aktif dibuat serta siswa ditempatkan di kelas. Tidak ada email undangan untuk siswa baru. Akun peran lain tetap menggunakan alur undangan yang lama. Guru tetap dapat memperbarui nama siswa, tetapi tidak dapat membuat akun baru; pembuatan siswa kini merupakan tindakan Admin.

Password tepat **12 karakter**: sebelas karakter awal adalah kombinasi huruf kapital Latin selain O/I/S dan angka selain 0/1/5 (minimal satu dari masing-masing), diikuti **tepat satu** karakter terakhir yang merupakan salah satu `!@#$*?`. Generator memakai Web Crypto dan sampling acak bebas bias; input manual diperiksa baik di UI, API Next.js maupun Edge Function.

RPC `reserve_student_password` hanya dapat dipanggil oleh service role. RPC terlebih dahulu membandingkan kandidat dengan hash sandi akun Auth lama menggunakan `crypt`, lalu menyimpan sidik SHA-256 ke tabel privat dengan primary key unik. Tidak ada password yang disimpan sebagai teks biasa atau dikirim balik dalam respons server. Reservasi yang gagal provisioning tidak digunakan ulang. Fungsi akan gagal tertutup jika hash lama tidak dapat diperiksa, agar tidak membuat klaim keunikan palsu. Ini menjamin kandidat tidak sama dengan password yang telah direservasi maupun password Auth yang dapat diperiksa **saat akun baru dibuat**; perubahan sandi dari alur pemulihan terpisah di kemudian hari tidak bisa dijamin unik secara permanen oleh ledger ini karena Auth menyimpan hash bersalt. Penegakan global untuk setiap perubahan password memerlukan perluasan semua jalur perubahan sandi.

Password siswa hanya diperlihatkan di sesi Admin yang membuatnya dan harus disalin/diserahkan secara aman. Pada impor TSV, Admin akan menerima password otomatis untuk baris siswa yang berhasil dalam laporan lokal; jangan unggah daftar password ke penyimpanan publik. Audit tidak mencatat password. Deploy migrasi database **sebelum** Edge Function baru; perubahan codebase melalui PR tidak mengubah lingkungan produksi sampai deployment dilakukan.
